# Resonance

Resonance — личный музыкальный плеер с собственной библиотекой, веб-интерфейсом и локальным музыкальным сервером. Новый интерфейс Resonance остаётся основой проекта; серверная логика предыдущего плеера переносится и адаптируется под него.

## Требования

- Node.js 20 LTS или новее
- npm
- Музыкальная папка на компьютере
- FFmpeg — только для записи тегов FLAC, M4A, OGG и OPUS

## Установка

```bash
npm run install:all
cp server/.env.example server/.env
```

Откройте `server/.env`, задайте `MUSIC_ROOT` и обязательно установите длинный случайный `RESONANCE_ACCESS_KEY`. Без ключа API намеренно не обслуживает запросы.

## Запуск

```bash
npm run dev
```

Frontend: http://127.0.0.1:5173  
API health: http://127.0.0.1:4317/api/health

Сервер API привязан только к loopback `127.0.0.1`. Для доступа с телефона используйте приватную сеть и защищённый reverse proxy (например, Tailscale Serve), не открывайте порт 4317 в интернет и не меняйте HOST на `0.0.0.0`.

## Команды

- `npm run build` — проверка TypeScript и production-сборка PWA.
- `npm run test:server` — unit-тесты серверных утилит.
- `npm run check:server` — синтаксическая проверка сервера.

## Сервер и данные

По умолчанию музыкальная папка — `Music` в домашнем каталоге ОС; путь можно задать через `MUSIC_ROOT`. Музыка остаётся на вашем компьютере. Индекс библиотеки строится из поддерживаемых аудиофайлов. Состояние синхронизации хранится в `server/resonance-sync.json`, резервные копии тегов — в `server/backups`; эти файлы не добавляются в Git.

## Безопасность

Не коммитьте `server/.env`, ключи доступа, музыкальные файлы или резервные копии. API требует ключ/HttpOnly-сессию, ограничивает доступ loopback-привязкой и проверяет пути файлов внутри музыкальной папки. Не публикуйте порт API напрямую в интернет.
