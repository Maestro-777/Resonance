# Resonance

Resonance — личный музыкальный плеер с собственной библиотекой, веб-интерфейсом и локальным музыкальным сервером. Новый интерфейс Resonance остаётся основой проекта; серверная логика предыдущего плеера адаптируется под него.

## Требования

- Node.js 20 LTS или новее
- npm
- Музыкальная папка на компьютере
- FFmpeg — только для записи тегов FLAC, M4A, OGG и OPUS

## Установка

**Windows:** запустите `1-УСТАНОВИТЬ.bat`. Скрипт установит frontend/backend зависимости, создаст `server/.env` и сгенерирует приватный ключ доступа. Для доступа с телефона после запуска приложения используйте `3-НАСТРОИТЬ-ТЕЛЕФОН.bat`. Для быстрой проверки локального API есть `4-ПРОВЕРИТЬ-СЕРВЕР.bat`.

**macOS / Linux:**

```bash
npm run install:all
cp server/.env.example server/.env
```

Задайте в `server/.env` путь `MUSIC_ROOT` и длинный случайный `RESONANCE_ACCESS_KEY`. Без ключа API намеренно не обслуживает запросы.

## Запуск

**Windows:** `2-ЗАПУСТИТЬ.bat`

**Любая ОС:**

```bash
npm run dev
```

Frontend: http://127.0.0.1:5173  
API health: http://127.0.0.1:4317/api/health

Откройте Настройки → Музыкальный сервер и вставьте ключ из `server/.env`. Затем просканируйте папку. Если используется стандартный путь, сервер ищет музыку в `Music` домашнего каталога ОС.

Для телефона установите Tailscale на оба устройства, войдите в один Tailnet, запустите `2-ЗАПУСТИТЬ.bat`, затем `3-НАСТРОИТЬ-ТЕЛЕФОН.bat`. Откройте HTTPS-адрес, который покажет Tailscale Serve. Публикуется только frontend; API остаётся на `127.0.0.1:4317` за Vite proxy.

## Возможности текущей интеграции

- Сканирование локальной музыкальной папки и чтение метаданных, включая ReplayGain и сведения о встроенных обложках.
- Реальная библиотека треков, альбомов и исполнителей; поиск по названию, исполнителю и альбому.
- Воспроизведение и потоковая передача с HTTP Range, перемотка, громкость, предыдущий/следующий трек, горячие клавиши.
- Очередь воспроизведения, shuffle, repeat, избранное, история и пользовательские плейлисты.
- Синхронизация избранного, очереди, истории, плейлистов, позиции воспроизведения, эквалайзера, длительности crossfade и оформления Resonance через домашний сервер.
- 10-полосный Web Audio EQ с пресетами, живой визуализатор спектра и автоматическая коррекция ReplayGain при наличии тегов.
- Загрузка аудиофайлов, тексты песен из соседних .lrc/.txt файлов, редактирование поддерживаемых тегов, просмотр списка резервных копий и восстановление выбранной копии.
- Offline-загрузки выбранных треков в IndexedDB и воспроизведение локальных копий на этом устройстве.
- PWA-установка, Media Session и управление воспроизведением с системных элементов управления, если это поддерживается браузером и ОС.
- Новая система тем, оформления и адаптации Resonance сохранена.

## Команды

- `npm run build` — проверка TypeScript и production-сборка PWA.
- `npm run test:server` — unit-тесты серверных утилит.
- `npm run check:server` — синтаксическая проверка сервера.

## Безопасность и хранение

Музыка остаётся на вашем компьютере. Сервер API принудительно слушает только `127.0.0.1`, требует ключ доступа/HttpOnly-сессию и проверяет пути файлов внутри музыкальной папки. Для доступа с телефона используйте приватную сеть и защищённый reverse proxy, например Tailscale Serve. Не открывайте порт 4317 в интернет и не меняйте HOST на `0.0.0.0`.

Не коммитьте `server/.env`, ключи доступа, музыкальные файлы или резервные копии. Состояние синхронизации хранится в `server/resonance-sync.json`, резервные копии тегов — в `server/backups`; эти файлы исключены из Git.

## Проверки и известные границы

GitHub Actions проверяет frontend production build, синтаксис сервера и unit-тесты утилит. Это не заменяет физическую проверку звука, Bluetooth, фонового воспроизведения, Media Session и установки PWA на реальном телефоне. Для записи тегов FLAC/M4A/OGG/OPUS требуется FFmpeg; WAV/AAC/WMA/AIFF доступны для чтения, но редактор тегов для них отключён.
